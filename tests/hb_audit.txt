Graph-lifting audit, 13 November 2026
===================================
Local completed checks:
- test_multilevel_hb_reference.cpp checks a seven-node path against hand-written
  square/ramp/constant coefficients, neighborhoods, unit weights and inverse.
  For x=[0,1,4,9,16,25,36], depth one coefficients are
  [0,-1,4,-1,16,-1,36]; depth two coefficients are
  [0,-1,-4,-1,16,-1,20]. Final roots are positions 0 and 4.
- The right endpoint has only node 4 as a coarse neighbor. Thus even the ramp
  [0,1,2,3,4,5,6] has final endpoint detail 2. This is a boundary-prediction
  limitation; constants are reproduced, but linear trends are not preserved
  at every boundary. Invertibility alone does not establish compressibility.
- Production extracted-method checks pass for path/irregular graphs, owner
  groups, imported remote plans, integer/floating inverse and stale setup.

Optimization review (no numerical behavior changed):
- Symbolic elimination can create dense coarse graphs, increasing both setup
  work and the number of terms in a predictor. It is not a sparse geometric
  multilevel interpolation construction.
- integerLiftingPlan returns a plan by value, including cached plans, so its
  vectors are copied during packet processing. Floating plans return references.
- Setup serialization stores every neighbor ID and every double weight,
  including unit weights. Setup uses MPI_Allgatherv, so plans are replicated.
- Existing measurements: quantization-first at 16 bits saves packet bytes but
  exported setup grows from 3,575,668 to 43,233,672 bytes; these counts exclude
  allgather replication. A larger setup cannot be inferred to be amortized by
  the single-step packet savings.
- Before-quantization HB modifies coefficient range and inverse error
  propagation. A common affine quantization range covers the coarse values
  and details. Negative and large coarse-level details can widen that range.
  This is a plausible mechanism, not yet a proven cause of the FCG breakdown.
