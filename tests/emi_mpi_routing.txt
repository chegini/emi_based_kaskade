MPI routing validation, stage 1
===============================

Branch: feature/inter-node-compression (EMI and Kaskade).
Executable option: --bddcMpiRouting 0|1 (default 0).
Transform-order runner option: --mpi-routing legacy|destination (default legacy).

Scope
-----
1 selects destination routing for iterative BDDC restriction/prolongation only.
It is supported for non-SDC MPI BDDC, including CG, FCG, FGMRES, compressed and
uncompressed transfers. All ranks must select the same option. Operator-audit
and preconditioner-probe paths reject it rather than silently ignoring it.
Raw starting steps and compressed continuation retain the same policy and
accumulate routing counters across the solver rebuild at the switch.

The old implementation Allgathervs all cross-rank packets to every rank; each
receiver then discards packets for other destinations. The opt-in implementation
batches by destination and uses Alltoall for counts and Alltoallv for payloads.
Same-rank copies remain local. The order in which each subdomain accumulates
contributions is unchanged: local packets first, then ascending source ranks,
with the producer's order retained inside each bucket. Neither quantization,
solver recurrence, stopping rule, split, transform, codebook policy nor packet
format changes. Exact numerical parity is expected and checked, not assumed.

MPI_Comm_split_type(MPI_COMM_TYPE_SHARED) discovers shared-memory groups once
when routing is enabled. The minimum world rank identifies each group. The
temporary communicator is freed immediately; no communicator survives finalize.
This identifies shared-memory capability; the MPI library chooses its transport.
No host-name parsing or assumption of contiguous rank numbering is used.

The six routing lines count sent logical payload bytes/packets by R/P and
same-rank / different-rank-same-node / inter-node endpoints. Each packet is
counted once at its producer. Their bytes must sum to the existing transmitted
logical payload counter. They exclude batch headers, MPI framing, count/control
collectives, setup, codebook training, coarse solves and global corrections.
They are NOT measurements of physical network traffic. MPI implementations may
internally forward collective messages through intermediate ranks.

Stage 1 does NOT turn off local compression. Setup weight/plan exchanges and
training-symbol gathers are also unchanged. Global scalar/correction collectives
still occur. A two-node topology does not imply all communication is compressed.

Opt-in local compression bypass (next stage)
-------------------------------------------
Application flag: --bddcLocalCompressionBypass 1 (default 0).
Checker flag: --check-local-bypass (adds one bypass case per solver).
Requires destination routing, compressed non-SDC MPI BDDC, affine ungrouped
quantization, no compression size threshold, and histograms off.

For each shared DOF, use the complete incident-subdomain owner set. If ANY two
owners share an MPI shared-memory domain, exclude that DOF from quantization on
EVERY copy, including remote producers/consumers. Other DOFs retain compression.
This deliberately keeps mixed local/remote DOFs exact on remote links too.
Sending raw originals locally but quantized copies remotely would violate
interface continuity and restriction feedback. The conservative exact policy
sacrifices some remote compression to preserve that consistency.

All-exact packets contain only raw values, with no codec metadata. All-exact
producers skip quantization, transforms, constant splitting, and encoding.
If the entire MPI job occupies one shared-memory node, EMI selects the ordinary
uncompressed transfer/solver backend for all steps, explicitly logged as
"nodes=1; backend=uncompressed; all steps use raw transfers". Requested codec
and warm-up options then have no work to do; solver family, tolerances, physical
time stepping and routing remain unchanged. The separate compressed solver
instantiation with raw packets produced roundoff-level trace differences in
the first cluster check (10 iterations and identical byte counts, but a roughly
4.04e-12 constant solution offset). We retain strict one-node parity checking
by using the same numerical backend, rather than relaxing its tolerance.
Existing exact corners are preserved. Packets combining remote-only and exact
DOFs use the existing codec plus exact trailers. Local-only values do not enter
the transform, quantizer range, or training symbols.

Node identity comes from MPI_Comm_split_type and the actual subdomain rank
ownership. The kernel tests use artificial maps only to cover mixed ownership
without cluster hardware. Production never uses artificial node identities.
MPI routing/transport remains unchanged: with self,tcp, raw same-node messages
still use TCP. This option bypasses the codec; it does not implement a new
shared-memory transport or remove global/coarse/setup MPI collectives.

Validation: first rebuild and run 10cells on one node with two ranks and
--check-local-bypass. All three new cases must match their uncompressed
destination controls exactly in snapshots/traces/iterations/logical bytes.
Then test two nodes/four ranks; require convergence, real inter-node traffic,
and byte accounting, while REPORTING solution errors against direct,
uncompressed, and all-compressed controls (no hidden accuracy threshold).
Placement now changes quantization, so multi-node numerical parity with the
old all-compressed method is not expected. Compression performance remains
unmeasured until working shared-memory transport and timing runs are available.

The build wrappers run the production transfer regression with the container's
Dune headers before rebuilding EMI. It covers both phases, before/after/both,
split off/on, 8/16/24 bits, raw packet sizes, no encoding on a single node,
all-remote parity, and exact mixed-owner contributions over repeated updates.

Why the local bypass is a separate numerical change
--------------------------------------------------
The compressed transfer keeps one reconstructed contribution per producer/DOF,
including its own copy and published-residual feedback. A DOF can be shared by
three or more subdomains spanning local and remote ranks. Sending original raw
values to local copies while remote copies receive quantized values would make
their assembled interface values disagree. A bypass needs a consistent policy
for these mixed owner sets (or node-level aggregation), plus explicit continuity
and feedback tests; it cannot be a simple conditional around the MPI send.

The orchestrator starts every solve through srun and Apptainer; no numerical
solve runs on the login node. Direct uses one rank on one node; BDDC uses
four ranks, two per node, with block placement. It preserves launcher PMIx
variables, explicitly selects the container Open MPI libraries, and uses
ob1 with self,vader,tcp, matching the successful transport check. Do not use
the single-node shell wrapper for this launch or nest mpirun inside srun.

The checker first verifies container/executable visibility on both nodes,
then runs the same 13 reference/paired cases. Destination runs must discover
two shared-memory domains and report positive inter-node bytes and packets
for both restriction and prolongation. The application pairs must retain
exact snapshots/traces/iterations/bytes. Logs and commands are retained,
including preflight output and allocation metadata. Each solve has a
10-minute Slurm step limit; the allocation's remaining time still applies.
Only after 10cells passes, repeat with --case pepe.

Compression remains enabled on local interfaces. These runs validate routing
before implementing a numerically consistent local compression bypass.

Pepe setup timeout diagnostic
----------------------------
The first four-rank/two-node Pepe legacy CG run was terminated by Slurm's
10-minute step limit before material replication completed. The last standard
assembly messages were rank 0's five owned subdomains; they do not show other
ranks' progress. This does not establish a CG failure or identify the bottleneck.

After rebuilding with build_emi_mpi_routing_cluster.sh, use the same host
checker command with --case pepe --setup-diagnostic-only. This runs exactly
one uncompressed legacy CG case, with no direct reference, compressed cases,
or parity comparison. The 10-minute limit is unchanged.

The option enables EMI_MATERIAL_TRACE=1 inside each application process.
Rank-local, flushed stderr messages show assembly, the error-consensus
collectives, matrix packing, length/payload broadcasts and reconstruction.
Subdomains in these messages are numbered from one; zero denotes a whole
stage. Elapsed seconds are local to each progress object (assembly and
exchange have separate clocks); they are not synchronized wall timestamps.
The observer adds no MPI calls, barriers, or arithmetic on solution data.
It is off by default and its timings are not performance measurements.
Inspect the new run's cg-uncompressed-legacy/run.log while it runs.

To isolate the Open MPI shared-memory transport in this container, repeat the
single setup diagnostic with --slurm-btl self,tcp. This sets the BTL selection
inside the container (a host export alone is overridden by the runner).
It disables vader and uses TCP also between different ranks on the same node;
self remains for send-to-self. It does not change compression or matrix data.
The default remains self,vader,tcp. No EMI rebuild is needed to change BTLs.
The selected transports are printed and saved in environment.json/command.sh.
This is a diagnostic comparison, not the desired final shared-memory policy
or a network-performance measurement. A successful TCP-only run would point
to a transport-dependent problem, but would not alone identify its root cause.

Pepe transport investigation and subsequent measurements
------------------------------------------------------
The next candidate is self,vader,tcp with the explicit setting
OMPI_MCA_btl_vader_single_copy_mechanism=none. In Open MPI 4 this disables
single-copy mechanisms, not the vader shared-memory BTL. It is a candidate
workaround, not yet validated on this cluster. Do not change PMIx security
components or rebuild the container as part of this first comparison.

In an active two-node/four-task allocation, from this repository:
python3 tests/run_emi_transport_probe.py \
  --slurm-container "$emi_sif" --kaskade "$emi_kaskade"

The probe builds a small MPI-only executable on a compute node. It first
uses self,vader (TCP absent) on one node/two ranks, then self,vader,tcp on
two nodes/four ranks. Both explicitly disable single-copy mechanisms.
It verifies every payload byte in broadcasts with rotating roots, ring
exchanges and variable-size destination exchanges, including 3 MB and 16 MB
messages. Shared-memory topology is checked. BTL selection logs and MPI
component information are retained. Each Slurm step has a three-minute limit;
failure stops the sequence. This does not rebuild or execute EMI.

If BOTH probe stages pass, run only the previously failing Pepe setup case:
python3 tests/run_emi_mpi_routing_check.py \
  --case pepe --ranks 4 --expected-nodes 2 \
  --slurm-container "$emi_sif" --kaskade "$emi_kaskade" \
  --slurm-btl self,vader,tcp --slurm-vader-single-copy none \
  --setup-diagnostic-only

Then validate Pepe's solver matrix with the same transport and
--check-local-bypass, omitting --setup-diagnostic-only. Do not claim transport
repair until the large-payload probe AND Pepe complete successfully. Keep
self,tcp as the known working fallback. This only restores local shared
memory; inter-node transport is still TCP, not a validated RDMA fabric path.

After transport validation, prepare a separate timing campaign: one warm-up
pair excluded, then at least five measured raw/bypass pairs alternating run
order, same allocation, executable, rank placement and thread count. Start
with FCG+split, 16 bits, transform-before. Keep histograms, transfer audits,
per-rank material tracing and full-state CSV export off for timing, while
retaining true residual checks, iterations and logical traffic counters.
Report median and spread for application wall time and the maximum-rank
solver wrapper separately; these include setup and are not codec bandwidth.
Do not subtract estimated codebook time or infer wire traffic from counters.
Any accuracy run with full-state output is separate from timing runs.

Time integration starts with FGMRES+split at 1, 5 and 10 physical steps,
dt=0.01 in model time units, with direct and same-family raw controls and
per-step full-precision errors. FCG/CG+split is currently guarded to ONE step;
FGMRES+split is guarded to at most TEN. Extending these limits is a separate
implementation and validation task, not a command-line override. Record raw
relative Euclidean error, absolute maximum error and mean offset; centered
error is diagnostic only. These are algebraic DOF errors, not FE or trace
Sobolev norms. Membrane-voltage errors need their own interface-jump diagnostic.

The residual tolerance remains 1e-7. A scientific solution-error acceptance
threshold has NOT been agreed. Obtain the required physical accuracy from
Fatemeh/Martin before marking these runs scientifically accepted; convergence
or a small centered error alone is insufficient. No new threshold is silently
applied by the transport/routing checks.
