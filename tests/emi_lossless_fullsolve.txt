EMI lossless MPI packet packing (opt-in; default OFF)

The application option --bddcLosslessPacking 1 uses the Kaskade lossless
packet wrapper. minVal, scale, quantized data and exact values are unchanged.
Requires compressed non-SDC MPI BDDC with destination routing, no constant
splitting, grouping, local bypass, audit/probe or raw-prefix schedule.
Existing FCG+split studies remain unchanged and do not use this option.

From the EMI repository on the cluster:
  mkdir -p output
  job=$(sbatch --parsable tests/submit_emi_lossless_fullsolve.sbatch)
  job=${job%%;*}
  printf '%s\n' "$job" > output/emi-packing-solve-job.txt
  tail -n 80 -F "output/emi-packing-solve-${job}.log"

Default: weak_32_h16, two nodes/four ranks, FCG, one time step, 16 bits,
transform before and after quantization, split OFF. To also test 12/24 bits,
append --bits 12 16 24 to the sbatch command. A fresh separate executable is
built under output; the root emiModel executable is not overwritten.

Every pair compares packing OFF/ON using the same executable and inputs.
PASS requires successful true-residual checks, exact initial/final CSV
snapshots, exact convergence traces, iterations, residual summaries and
unchanged pre-wrapper logical byte counts. Source/input hashes are checked.
Results: output/emi-packing-solve-JOB/validation/{summary.csv,PASS}.

The additional saving uses original vs packed routed message bytes, including
record/wrapper overhead. These are inter-rank messages, including same-node
MPI transfers; intra-rank copies and MPI implementation framing are excluded.
Existing compression/routing counters still describe pre-wrapper logical bytes.
This is correctness validation, not repeated performance timing.

Omitted tail-length field (cluster full-solve validation passed)
---------------------------------------------------------------
Formats 5/6 extend 3/4: retain the uint16 Huffman length but omit the uint16
tail length. Exact values prevent deriving that length from the body boundary
alone. For an encoded record, the existing uint32 original-slot-count field
therefore stores the exact-double count instead; its width does not change.
Raw records keep the original slot-count meaning and their bytes unchanged.

After restoring any shared affine header, the compact encoded body contains:
  minVal + scale: 8 bytes; Huffman length: 2 bytes;
  Huffman stream H; tail stream T; E exact doubles (8*E bytes).
The envelope supplies the compact body boundary and E. Thus:
  T = compact body bytes - 10 - H - 8*E.
Checked subtraction rejects impossible counts/lengths; T must fit uint16.
The decoder restores the two uint32 lengths, zero padding to eight-byte
alignment, exact values and original slot count before the numerical codec.
Sender-side comparison still requires exact original packet bytes and order.

Two bytes per encoded record are saved relative to formats 3/4. Existing
formats remain candidates, so adaptive packing cannot exceed the previous
best size. Large streams retain previous formats. No quantization setting,
minVal, scale, tolerance, solver or splitting configuration is changed.

The existing full-solve submission script rebuilds this version. New output:
  two_length_packer_bytes: best size using modes 0..4 on the same live packets;
  tail_length_bytes_saved: two_length_packer_bytes minus packed_routed_bytes;
  tail_length_savings_percent: percentage relative to two_length_packer_bytes.
The stream_length_* columns isolate shortening both lengths (wide to short),
while tail_length_* isolate omission (two short lengths to one). Total saving
remains relative to compressed routed messages without lossless packing.
The raw transport length-compaction log line includes both length changes.
Previous cluster results above concern earlier formats. Fresh full-solve
validation of tail omission is recorded below.

Endpoint-plan reuse
---------------------------------------------
Packing remains opt-in; minVal, scale and every reconstructed packet byte are
unchanged. The first nonempty message per directed MPI peer and transfer phase
carries the ordered source/destination IDs. Later messages omit the two int32
IDs per record (8 bytes) only when the entire ordered sequence matches. A
changed sequence refreshes the plan using explicit IDs. Empty messages retain
the plan; empty payload records retain their positions. Raw fallbacks and
changes of packet size do not change the endpoint identity.

The selector high bit identifies implicit IDs, so no extra selector byte or
setup collective is introduced. Both ends must use the updated implementation;
plans rely on reliable ordered delivery on the same phase/peer channel.
Restriction and prolongation have separate plans.

The existing submission script builds a fresh executable and checks exact
solution, residual-trace and iteration parity. It now requires both plan
establishment and reuse. endpoint_plan_id_bytes counts IDs actually sent in
initial/refresh messages; it is already INCLUDED in packed_routed_bytes, not an
additional charge. endpoint_ids_bytes_saved equals explicit_id_packer_bytes
minus with_exact_count_packer_bytes (or packed_routed_bytes before count
omission was added). Its percentage uses the explicit-ID packer as the
denominator. Tail-length savings stop at explicit_id_packer_bytes, avoiding
double counting the new endpoint savings. Total additional_savings_percent
continues to compare the original compressed routed messages with the final
packed messages. These are application transport bytes, not total network
traffic. Previous cluster results above validate the earlier format only.

Exact-double count reuse
--------------------------------------------------------
The generic transport decoder does not directly inspect an interface mask.
Instead it learns exact-double counts from validated existing packet fields,
separately per restriction/prolongation phase and directed MPI peer. The sender
checks the count extracted from every actual encoded packet on every call.
When ordered endpoints and encoded/raw modes/counts match, formats 5/6 omit
four bytes per encoded record. A reserved selector bit identifies this layout;
no extra selector byte or setup message is added. Raw records keep explicit
slot counts, including empty raw records. Changed counts/modes refresh count
knowledge without unnecessarily retransmitting unchanged endpoint IDs. Changed
endpoints refresh both plans. Empty messages retain plans. Wide-length and
legacy formats remain fallbacks. No numerical parameter or value is modified.

The existing full-solve submission script tests the updated shared header. It
requires nonzero exact-count savings and exact solution/trace/iteration parity.
with_exact_count_packer_bytes is the previous endpoint-planned size, including
all initial/refresh fields; packed_routed_bytes is the final actual size.
exact_count_bytes_saved = with_exact_count_packer_bytes - packed_routed_bytes.
exact_count_savings_percent uses with_exact_count_packer_bytes as denominator.
Endpoint-ID savings now stop at with_exact_count_packer_bytes, so they do not
count the new omission twice. Total savings still compare final bytes to the
original compressed routed messages. Initial plan costs are already included.

Packing remains disabled by default. Constant splitting/grouping restrictions
are unchanged. All MPI ranks must use this updated decoder. These tests cover
scalar packets; they do not claim compatibility with unsupported layouts.
Earlier cluster jobs above validate previous formats; the count-omission
validation results are recorded below.
